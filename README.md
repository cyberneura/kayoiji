# Kayoiji (通い路)

macOS の日本語入力メソッド。「かな」キーで日本語入力に、「英数」キーで直接入力に切り替える。

オプションの**自動切り替え**を有効にすると、日本語と英語を、キーで切り替えずに入力できる。
打鍵の並びと直前の入力から、いま打っている単語が英語か日本語かを判定する。
`tatoe` まで打てば日本語だと分かるので、その時点でかなに切り替える。`for ` は英語のまま通す。

```
watasiha Tauri de apuriwo tukurimasu   →  私はTauri でアプリを作ります
git status wo jikkousuru               →  git status を実行する
for the people, by the people.         →  for the people, by the people.
```

自動切り替えは、既定では無効。

## 仕組み

Kayoiji は macOS の入力メソッド (InputMethodKit) として動く。「システム設定 → キーボード → 入力ソース」で
追加して、入力メニューから選んで使う。メニューバーに独自のアイコンは出さない。

- 入力中のかなは、未確定文字列として表示する
- 変換候補は、未確定文字列の近くに出る小さなウインドウに表示する
- 自動切り替えでは、判定がつくまでの英字も未確定文字列として表示する。英語と決まった時点で確定し、
  その単語の残りの打鍵はそのまま入力先へ通す。日本語と判定したら、未確定文字列をかなに切り替える

アプリは Tauri で作っている。プロセスの中で `IMKServer` を動かし、候補ウインドウと設定画面を
WebView で表示する。

入力メニュー (メニューバーの入力ソースのメニュー) には、次の項目がある。

| 項目 | 動作 |
|---|---|
| 英語と日本語を自動で切り替える | 自動切り替えを有効にする、または無効にする。有効な間はチェックが付く。設定画面からも変えられる |
| Kayoiji の設定… | 設定画面を開く |
| About Kayoiji | バージョン番号とビルド日時を表示する |

## 英語か日本語かの判定

自動切り替えが有効な時の動作。上から順に評価する。利用者の訂正 (7) で覚えた単語は、判断データベースの決め打ちより優先する。

1. **判断データベース** (`crates/kayoiji-core/data/rules.toml`)。`for ` は英語、`tatoe` は日本語、のような決め打ち。
   設定ディレクトリの `rules.toml` に同じ書式で規則を足せる
2. **ローマ字として読めない打鍵列** (`th`, `st`, `ck` など) は、その単語を英語で確定する
3. **単語の途中**: その打鍵列で始まる英単語がほとんど無く、かなとして読んだ時に日本語として十分ありそうなら、
   その場で日本語に切り替える
4. **単語の区切り** (空白): 英単語としての出現確率と、かなを日本語として読んだ時の確率を比べる。
   日本語なら、空白は変換の指示として扱う。英語なら、単語を確定して空白を入力する
5. **打鍵の間隔**が 200ms (設定で変更可) を超えた単語は、英語で確定する
6. **日本語を確定した後**は、日本語の入力が続いているとみなす。次の単語は最初からかなで表示し、
   ローマ字として読めない、または英単語だと分かった時点で英字に戻す。英単語が 2 語続いたら英語の入力に戻ったとみなす
7. **利用者の訂正**を覚える。Esc で英字に戻した単語は英語、Ctrl+J で読み直した単語は日本語として、次から扱う

全角の英数字・空白は出力しない。記号は、日本語の入力中だけ次のものが変わる (ローマ字の表は Mozc のもの)。

- `,` `.` `[` `]` `-` `~` は「、」「。」「「」「」」「ー」「〜」になる
- `z` に続けて打つ `z.` `z,` `z/` `z-` `z[` `z]` `zh` `zj` `zk` `zl` は「…」「‥」「・」「〜」「『」「』」「←」「↓」「↑」「→」になる

## 入力モード

| モード | メニューバー | 動作 |
|---|---|---|
| 日本語入力 | あ | すべての打鍵を日本語として入力する |
| 自動切り替え | 通 | 英語か日本語かを判定しながら入力する |
| 直接入力 | OS の英字 (`A` など) | Kayoiji を離れて、OS の英字のキーボード配列 (ABC など) で入力する |
| 英文チェック | あ / 通 のまま | 英文を未確定文字列として受け取り、綴りの訂正候補、訂正文、日本語訳を表示する |

「英数」キーで直接入力に、「かな」キーで日本語入力にする。
PC 用のキーボードでは、「無変換」が「英数」、「変換」が「かな」にあたる。

直接入力は、Kayoiji の中のモードではない。「英数」を押すと、Kayoiji が OS の英字のキーボード配列を選ぶ。
「かな」を押すと、OS が Kayoiji を選び直す。このため、OS の入力ソースに英字のキーボード配列 (ABC など) が
入っている必要がある。

自動切り替えを有効にすると、「かな」キーで入るモードが、日本語入力から自動切り替えに変わる。
切り替えは、入力メニューの「英語と日本語を自動で切り替える」か、設定画面で行う。

入力ソースの一覧に並ぶ Kayoiji は 1 つだけ。日本語入力 (`あ`) と自動切り替え (`通`) はアイコンの違う入力モードで、
設定に合う側だけを有効にしてある。設定を切り替えると、一覧の Kayoiji が入れ替わる。

### 日本語入力

- 何も入力していない時の文字のキーは、記号や数字も含めて、日本語の入力を始める。
  それ以外のキー (Space、Enter、矢印、ショートカット) は、そのまま入力先へ通す
- 入力中に「英数」を押すと、入力中の文字列を表示されているとおりに確定してから、直接入力にする
- 「かな」は、何も変えない
- 大文字から始めた入力は、かなにしない (`Tauri`)

設定の「英語を打ち始めたら、日本語入力を自動で抜ける」(既定は無効) を有効にすると、次の打鍵で、入力中の文字列を
確定して直接入力に切り替える。「英数」を押した時と同じく、かなは変換せずに表示のとおりに確定する。「かな」で戻る。

- 大文字の英字 (Shift + 英字)。その大文字は、直接入力の打鍵として入力される
- ローマ字の規則に無い並び (`st`、`pl`、`ck` など)。読める所まではかな、残りは打ったままの英字で確定する
  (`kyouhapl` で「きょうはpl」)。1 文字だけでは抜けない
- 英語が続く記号 (`/`、`@`、`#` など)。その記号は、直接入力の打鍵として入力される。
  日本語の記号になる `,` (、) `.` (。) `[` (「) `]` (」) `-` (ー) `~` (〜) と、`'` (`n'` の「ん」)、
  文末の `!` `?` では抜けない
- 何も入力していない時のスペース。入力中のスペースは、いつもどおり変換する

`thi` (てぃ)、`dhi` (でぃ)、`twu` (とぅ)、`kwa` (くぁ) のように規則にある並びは、日本語のまま入力する。
`the` や `this` のような `th` で始まる英単語と、`made` のようにローマ字として読める英単語では抜けない。

### 自動切り替え

- 入力中に「英数」を押すと、入力中の文字列を打鍵したままの英字で確定してから、直接入力にする
- 何も入力していない状態で「かな」を押すと、次の入力を判定せずに日本語として始める。
  記号から始まる入力に使う (「かな」→ `.` →「かな」で「。」を「…」に変換する)。効くのは次の 1 回だけ
- かなの入力中の「かな」は、変換する

どちらのモードでも、日本語の入力は確定の操作をするまで続く。時間が経っても、カーソル移動のキーを押しても確定しない。

## キー操作

| キー | 動作 |
|---|---|
| Space | 変換する / 次の候補 |
| Enter | 確定する |
| ← / → | 変換中: 候補を選ぶ文節を移る |
| Shift+← / Shift+→ | 変換中: 文節を縮める / 伸ばす。後ろの文節は変換し直す |
| ↑ / Shift+Space | 前の候補 |
| 1〜9 | 候補を番号で選ぶ。最後の文節なら確定し、それ以外は次の文節へ進む |
| Backspace | かなを 1 文字消す / 変換をやめてかなに戻る |
| Esc | かなの入力中: 入力を取り消す。変換中: 変換をやめてかなに戻る |
| Ctrl+; / F10 | かなの入力中でも変換中でも、打ったままの英字に戻して確定する |
| Ctrl+K / F7 | カタカナにする |
| 英数 / 無変換 | 直接入力 (OS の英字のキーボード配列) にする |
| かな / 変換 | 日本語入力にする (自動切り替えが有効なら、自動切り替えにする)。何も入力していない時に続けて 2 度押すと、英文チェックにする |

自動切り替えでは、次のキーの動作が変わる。

| キー | 動作 |
|---|---|
| Esc | かなの入力中: 打ったままの英字に戻して確定する (その単語を英語として覚える)。変換中: 変換をやめてかなに戻る |
| Ctrl+; / F10 | かなの入力中でも変換中でも、打ったままの英字に戻して確定する (その単語を英語として覚える) |
| Ctrl+J | 直前の単語 (または打っている途中の単語) を日本語として読み直す (その単語を日本語として覚える)。確定済みの単語は、キャレットの直前にその単語がある時だけ読み直す |
| かな / 変換 | かなの入力中: 変換する。入力中でなければ、次の入力を日本語として始める |

### 自動切り替えで、日本語の入力中に英語を入れる方法

| 場面 | 操作 |
|---|---|
| ローマ字として読めない英単語 (`for`, `the`, `string`) | 何もしない。読めなくなった時点、または空白の時点で英字に戻る |
| ローマ字として読めてしまう英単語 (`made`, `site`, `to`) | Esc。その単語だけが英字に戻り、次からは英語として扱う |
| 大文字で始まる単語 (`Tauri`, `API`) | 何もしない。大文字を含む単語は英語として扱う |
| 英語をしばらく続けて打つ | 「英数」で直接入力にし、終わったら「かな」で戻す |

### 英文チェック

何も入力していない時に「かな」を続けて 2 度押す (0.4 秒以内) と、英文チェックになる。直接入力
(OS の英字のキーボード配列) からは、1 度目の「かな」で Kayoiji に戻り、続けて押した 2 度目で入る。打った英文は
未確定文字列として表示され、Enter を押すまで確定されない。候補ウインドウ (入力位置の下。下に空きが無ければ上) に、次の 3 つを表示する。

- **綴り**: 綴りが誤っている単語と訂正候補。OS のスペルチェッカーで、打つたびに調べる
- **英文**: 文法や言い回しを直した訂正文。直す所が無ければ「自然な英語です」
- **訳**: 訂正文の日本語訳

綴りの訂正候補と、訂正文・訳は、打鍵が 0.5 秒止まると作る。訂正文と訳は、Mac の言語モデル
(Apple Intelligence) が端末の中で作り、
1〜3 秒で表示する。打った英文を外部へは送らない。Apple Intelligence が使えない Mac では、綴りだけを表示する。

| キー | 動作 |
|---|---|
| Enter | 英文を表示のとおりに確定する。英文チェックは続く |
| Tab | 英文を訂正案に置き換える。訂正文があればそれ、まだ無ければ綴りだけを直した文 |
| Esc | 英文を捨てる。何も打っていない時は、英文チェックをやめて直接入力にする |
| Option / Command を付けたキー | 英文を確定してから、そのキーを入力先に通す |
| 英数 | 英文を確定して、直接入力 (OS の英字のキーボード配列) にする |
| かな | 英文を確定して、日本語入力にする (自動切り替えが有効なら、自動切り替えにする) |

言語モデルの訂正は、いつも正しいとは限らない。訳は粗く、細部が落ちることがある。命令の形をした英文は、
意味の違う文に直されることがある。メニューバーのアイコンは日本語入力の時と同じままで、英文チェックで
あることは候補ウインドウで分かる (英文を打つまでは何も出ない)。

### 絵文字

変換の候補には、読みや漢字の候補 (「ねこ」なら「猫」) をキーワードにした絵文字が、単語とひらがな・カタカナの後に
出る (「ねこ」→ 猫 / ねこ / ネコ / 🐱 / 🐈 …)。肌の色の違いは出さず、基本の色だけを出す。

「えもじ」を変換すると、「絵文字」の次に「絵文字を探す」が出る。選んで確定すると絵文字モードになり、
すべての絵文字を検索語か分類 (スマイリーと感情、動物と自然 …) で探せる。検索語はローマ字で打つと
かなになり、打ったままの英字で英語のキーワード (`cat` など) も引く。空白を含むキーワードは、空白を詰めて打つ
(`red heart` は `redheart`)。「絵文字を探す」は、「えもじ」だけを変換した時に出る。

| キー | 動作 |
|---|---|
| 文字のキー | 検索語を打つ。打つたびに一覧が変わる |
| ← → ↑ ↓ / Space | 絵文字を選ぶ |
| Shift+← / Shift+→ | 前後の分類の一覧にする。検索語は消す |
| Tab | 選んでいる絵文字の、肌の色の違いを出す (← / → で選ぶ)。出ていれば閉じる |
| Enter | 選んだ絵文字を確定して、絵文字モードをやめる |
| Backspace | 検索語を 1 文字消す。検索語が空なら、絵文字モードをやめる |
| Esc | 肌の色の違いを閉じる。出ていなければ、絵文字モードをやめる |
| 英数 | 絵文字モードをやめて、直接入力にする |

### 変換の学習

- Enter や次の文字の入力で確定した時に、文節ごとに選んだ候補を覚える。同じ読みの文節を次に変換すると、
  選んだ候補が先頭に出る
- 文節を区切り直して (Shift+← / Shift+→) 確定すると、区切り直した範囲を 1 語として覚える。
  「かよいじ」を「かよい」「じ」に分けて「通い」「路」を選んで確定すると、次からは「かよいじ」が
  「通い路」になる。「かよいじを」のように助詞が続く時や、文の途中でも「通い路」になる
- 語として覚えるのは、範囲の末尾の助詞や助動詞を除いた部分。「かよい」「じを」を「通い」「路を」で
  確定しても、覚えるのは「かよいじ → 通い路」
- 覚えた語と同じ読みで別の候補を選んで確定すると、その語は忘れる

語として覚えないもの:

- 文節を分けて、辞書の 1 語を選んだだけの範囲。「きょうは」を「きょう」「は」に分けて「京」を選んでも、
  語としては覚えない。文節をまとめて辞書の 1 語を選んだ時 (「つき」「いち」をまとめて「月一」) は覚える
- ひらがなのまま・カタカナ・記号・日付のように、辞書の語ではない候補を選んだ文節を含む範囲
- 読みが 12 文字を超える範囲
- カタカナにする変換 (Ctrl+K / F7) から区切り直した範囲

文節ごとに覚えた候補は、読みが文節とちょうど一致する時だけ効く。「きょう」で「京」を選んでも、
「きょうは」の変換は変わらない。覚えた語は、英語か日本語かの判定には使わない。

覚えた語の読みが「名詞 + 助詞」とも読める時 (「ゆきが」を「雪賀」) は、その読みだけを変換した時に語が出る。
文の中の「雪が積もる」は変わらない。ただし、語が出た文節をそのまま確定すると、文節ごとの学習として
「ゆきが → 雪賀」を覚えるので、以後は文の中でも「雪賀」が先頭に出る。「雪が」を選び直すと、語ごと忘れる。

### 記号と日付

変換の候補には、かな漢字変換の結果に続いて、読みに一致する記号と日付が出る。

| 読み | 候補 |
|---|---|
| みぎ / ひだり / うえ / した / やじるし | → ← ↑ ↓ など |
| きごう / けいせん / かっこ / まる / さんかく … | 記号、罫線 |
| かお / かおもじ / にこ / ばんざい … | 顔文字 |
| 。 、 ・ | … ‥ ． ， など |
| きょう / きのう / おととい / あした / あさって | `2026-11-25` `20261125` `2026/11/25` `2026年11月25日` `11月25日` |
| こんげつ / せんげつ / らいげつ | `2026-11` `202611` `2026/11` `2026年11月` `11月` |
| ことし / きょねん / らいねん | `2026` `2026年` `令和8年` |

日付の候補は、選んでも次回の先頭にはしない (日ごとに変わるため)。

## インストール (macOS)

Apple Silicon の Mac 用。Homebrew で入れる。

```sh
brew install --cask cyberneura/tap/kayoiji
```

`~/Library/Input Methods/Kayoiji.app` に入る。入れた後に「システム設定 → キーボード → 入力ソース → 編集 → +」で
「日本語」を選び、Kayoiji を追加する。一覧に出ない時は、ログインし直す。`brew upgrade` で新しい版に置き換えた時は、
ログインし直すまで前の版が動いていることがある。

### ソースからビルドして入れる

```sh
pnpm install
pnpm data                    # 辞書の元データを取得して data/build に辞書を作る (初回だけ。約 125MB を取得する)
pnpm helper                  # 英文チェックの補助プロセスを data/build にビルドする (インストールのスクリプトも行う)
./scripts/install-macos.sh   # ビルドして ~/Library/Input Methods/Kayoiji.app に置き、OS に登録する
```

[j-menu](https://github.com/cyberneura/j-menu) を使っているなら、`j` →「Install locally」で同じスクリプトが動く。

初回は「システム設定 → キーボード → 入力ソース → 編集 → +」で「日本語」を選び、Kayoiji を追加する。
一覧に出ない時は、ログインし直す。

もう一度実行すると、新しい版に置き換わる。入力ソースとして追加済みなら、追加し直す必要は無い。
入力モードやアイコンが変わった版に置き換えた時は、ログインし直すまで、システム設定の一覧やメニューバーに
前の版の内容が残ることがある。スクリプトがログインし直すように案内した時は、ログインし直してからもう一度実行する。

- 辞書が無ければ `pnpm data` を先に実行する
- 同梱する辞書でエンジンが開けない時は、インストール済みの版に手を付けずに止まる
- 新しい版を OS に登録できるまで、今の版を退避して残す。登録に失敗したら、今の版に戻す
- 動いている古い版を止める。次に入力する時に、OS が新しい版を起動する
- 入れ替えた後に Kayoiji の入力モードがどれも有効でなければ、先頭の入力モード (日本語入力) を有効にする

## KayoijiPad

エンジンを、入力メソッドとして入れずに試すためのアプリ。テキストエリアとコピーボタンだけがある。

```sh
pnpm pad          # 開発モードで起動する
pnpm pad:build    # target/release/bundle/macos/KayoijiPad.app を作る
```

- OS の入力ソースが英字の時は、テキストエリアの打鍵を内蔵のエンジンで処理する。未確定文字列は選択範囲として表示する
  (変換中は、候補を選んでいる文節だけを選択する)
- 入力モードは、コピーボタンの隣のボタンに出る (`あ` = 日本語入力、または自動切り替えで次の入力が日本語 / `自動` = 自動切り替え /
  `A` = 直接入力)。クリックでも切り替わる。
  macOS で他の IME を入れていると、「英数」「かな」キーは OS の入力ソースの切り替えに使われるので、このボタンを使う
- 「自動切り替え」ボタンで、自動切り替えを有効にする。起動し直しても、前の状態を覚えている
- OS の入力メソッド (Kayoiji 本体を含む) が有効な時は、入力を OS に任せる。入力メソッドとして入れた Kayoiji の確認にも使える
- 判断データベースは、標準の規則に入力メソッド本体の `rules.toml` を重ねて読む
- 選んだ候補や訂正は、起動している間だけ覚える。入力メソッド本体の学習内容には書き込まない

## 開発

必要なもの: Rust、Node.js、pnpm、Xcode のコマンドラインツール (`swift`)。

入力メソッドは OS が起動するので、`pnpm tauri dev` では入力を試せない (設定画面と候補ウインドウの
画面だけが動く)。入力メソッドとしての動作を試す時は `./scripts/install-macos.sh` で入れ直す。エンジンの動作は KayoijiPad と CLI で確認できる。

```sh
cargo test --workspace     # ユニットテスト
pnpm test                  # フロントエンドのユニットテスト
pnpm check                 # フロントエンドの型検査
cargo run --release -p kayoiji-cli -- type "tatoeba korehapendesu "   # 打鍵の列を入力した結果
cargo run --release -p kayoiji-cli -- explain kore site               # 判定に使う値
cargo run --release -p kayoiji-cli -- evaluate                        # 実データでの精度
```

`kayoiji-cli` は判定の動作を調べるためのものなので、エンジンを自動切り替えで動かす。
`kayoiji-cli type` の打鍵の列では、空白が変換・区切り、`{enter}` `{esc}` `{bs}` `{ja}` `{en}` `{kata}`
`{wait}` が特殊キーと打鍵の間隔を表す。

### かな漢字変換

変換エンジンは Mozc そのものではない。Mozc の OSS 辞書 (約 130 万語) と連接コスト行列を使い、
ラティスを作って Viterbi で最小コストの経路を求める処理を、このリポジトリで実装している。
2 位以降の候補は、後ろ向きの A* 探索で取り出す。

- 最小コストの経路を、自立語の始まりで文節に区切る (助詞・助動詞・接尾語・非自立語は前の文節に付ける)
- 文節ごとに候補を持つ。文節の長さを変えると、その文節を読みから変換し直し、後ろの文節も区切り直す
- 記号と顔文字は、Mozc の `symbol.tsv` と `emoticon.tsv` から読みで引く

Mozc が持つ機能のうち、予測変換、数字の変換 (漢数字など)、郵便番号、単語登録、再変換は無い。

### 利用者のデータ

`~/Library/Application Support/com.cyberneura.inputmethod.Kayoiji/` に置く。

| ファイル | 内容 |
|---|---|
| `settings.toml` | 設定 (`auto_switch`: 自動切り替え、`leave_japanese_for_english`: 英語を打ち始めたら日本語入力を抜ける、`sequence_timeout_ms`: 自動切り替えで、ひと続きの入力とみなす打鍵の間隔) |
| `rules.toml` | 判断データベースの追加分 |
| `learning.json` | 文節ごとに選んだ候補、区切り直して覚えた語、英語・日本語の訂正 |

読めないファイルがあっても、入力メソッドは既定の内容で起動する (`rules.toml` は標準の規則だけ、`settings.toml` は既定値)。
読めなかった理由は設定画面に出る。壊れた `learning.json` は `learning.json.broken` に退避して、空の記録から始める。

## 制限

- Windows 版は無い。Windows の IME は TSF のテキストサービス (COM の DLL) として作る必要があり、未実装
- 予測変換、数字の変換、単語登録、再変換は無い
- 確定済みの単語の読み直し (Ctrl+J) は、キャレットの直前の文字列を返さない入力先では使えない
- 「次の入力を日本語として始める」状態は、入力メニューのアイコンに出ない
- 確定済みの単語の読み直し (Ctrl+J) は、キャレットの位置を返さない入力先では単語を消せない
- 候補ウインドウは通常のウインドウなので、フルスクリーンのアプリの上には出ないことがある
